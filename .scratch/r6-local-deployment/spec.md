# R6 本地稳定部署交付 Spec

Status: Ticket 01–04 已完成；PR60 已合并（9a70601），交付与分支清理完成。运行验收仍绑定 clean runtime 2b4a8c8；电脑 / Docker daemon 重启恢复尚未验收，限制见 docs/acceptance/local-deployment-v1.md。

## Problem Statement

现有 Compose 是容器开发入口，具有源码挂载与热更新，不代表固定版本应用的稳定交付。用户目前没有云服务器，也暂不需要互联网访问，希望先在当前电脑上获得可复现安装、后台运行、持久化、升级与兼容回滚的完整闭环。

## Solution

首版目标为当前 Windows + WSL2 Linux x86_64 + Docker Engine / Compose 电脑，通过 Windows 浏览器访问仅本机可达的同源 HTTP 网页与 API。使用现有确定性合成销售演示数据，保持既有查询、分析、权限、历史、成果与导出 Contract。

本机按指定版本构建固定版本镜像，容器完成应用构建和初始化；无需额外安装宿主 Python / Node。运行不挂载源码、不热更新。前端打包后由现有 API 静态网页入口提供，不新增业务调用链。采用单 API 进程、CPU / FP32 Embedding，沿用外部 LLM。

“本地部署”不等于离线：首次需要联网获取镜像、锁定依赖与固定 revision 的 Embedding 模型，之后复用缓存；日常问数与经营分析需要访问外部 LLM。

## User Stories

- 开发者可以按照文档，在独立空数据环境中完成指定版本的构建、配置、初始化及启动，并识别安装失败的步骤。
- 使用者在 Windows 浏览器登录，完成问数、追问、经营分析、历史查看、保存成果和导出。
- 使用者关闭启动终端后应用继续运行，显式停止后保留数据，电脑或 Docker 重启后可手动再次启动。
- 维护者可以允许短暂停机升级，确认兼容性后回滚到旧版本，保留账号、历史与保存成果。

## Observable Behavior

### 环境与配置隔离

- 开发、测试 / 部署验收、稳定运行使用独立配置、端口与持久资源身份；不依赖仅修改 `CHATBI_ENV` 实现隔离。
- 稳定运行有独立数据库账号、业务库 / Control DB 数据卷、Qdrant 数据与 RAG 发布索引；同一演示数据内容在独立环境初始化，不导入现有开发账号与历史。
- 固定 revision 的模型缓存可复用；应用读取模型与发布资产，不因启动修改缓存或开发索引。模型路径 / 来源身份遵守现有 manifest 校验。
- 可以沿用同一外部 LLM 服务；真实配置不进入 Git、镜像、报告或日志。管理员密码隐藏输入，不通过命令参数传入。
- 保持指定账号、现有 Cookie 登录、CSRF 和 owner 权限检查；业务数据共享及个人历史隔离沿用现有 Contract。端口仅绑定本机回环地址。

### 显式首次初始化

- 配置后显式完成基础设施初始化、数据库迁移、固定 revision 模型准备、RAG 构建和首个管理员创建。
- 空业务数据卷使用现有 Sales Mart Schema 和确定性合成 Seed；再次启动不重播 Seed、不重置账号或历史。
- 日常启动只检查运行条件，不自动迁移、下载模型、重建索引或创建管理员；缺少条件时失败并提示具体处理步骤。
- 迁移保持现有幂等行为；已有管理员时重复创建按现有 Contract 拒绝，不覆盖密码。

### 启动、停止与诊断

- 一个明确入口可后台启动完整应用与所需基础设施；另一个明确入口停止该稳定环境，保留持久数据与资产。
- 关闭终端不终止已启动的后台应用；电脑或 Docker 重启后需手动启动完整应用，不承诺系统自动启动。
- 启动成功必须明确对应的版本与本机访问地址；HTTP 存活不被解释为真实问数或动态依赖就绪。
- 配置缺失、端口冲突、索引来源不匹配、依赖不可用或启动失败时给出安全诊断与非零退出状态；不杀未知进程、不重置数据、不输出完整配置或 Secret。
- 状态和日志入口可定位阶段与对应环境；操作不能停止或修改另一环境的服务与资源。

### 固定版本、升级与回滚

- 记录源提交、镜像身份及适用数据库 / RAG 资产身份，不能仅凭可变镜像标签宣称同一版本。
- 升级允许短暂停机：停止旧应用，显式执行所需迁移 / 资产准备，启动指定新版本并检查核心流程。日常启动不承担隐式升级。
- 升级与回滚保留账号、历史和保存成果；执行中任务与临时对话不承诺跨升级恢复，不扩展 R4 execution 或 checkpoint 的现有恢复语义。
- 仅允许启动与当前数据库和发布资产兼容的旧版本；不兼容时拒绝并说明原因，不自动反向迁移、删除表或删除卷。
- 迁移 / 启动失败保留现存数据，明确失败阶段；旧版本兼容时可按文档恢复，否则不宣称自动恢复成功。
- 兼容性判定、版本描述文件与命令组织由设计明确，并经设计审查，不预设所有历史版本都可回滚。

## Implementation Decisions

### 已确认

- 当前电脑为首版交付与验收目标；仅本机 HTTP 同源访问，既有 Cookie / CSRF，不新增公网访问或 HTTPS 部署。
- 现有销售合成数据；本机固定版本镜像构建，无镜像仓库；容器构建 / 初始化，无宿主 Python / Node 要求。
- 单 API 进程、CPU / FP32、外部 LLM、显式初始化与手动启动、独立持久环境。
- 允许短暂停机；保留长期数据；兼容旧版本回滚，不兼容拒绝，不做金丝雀发布。

### 留给 Design / Ticket

- Compose 文件与项目命名、端口配置、命令入口、固定版本标识和构建产物布局。
- 兼容性描述与确定性检查方式，升级失败后的操作步骤和可复现验收版本对。
- 独立配置模板、最小权限装配、模型缓存复用与索引路径 / manifest 身份处理。
- 镜像沿用既有锁定依赖，包含 R5 所需 Chromium / 字体等运行资产；具体构建组织属于设计。

以上局部选择不能放宽已确认行为、安全门禁或数据保护约束。若事实不足以实现兼容性判定，应在设计阶段指出并澄清，不用“旧镜像仍在”代替兼容性证明。

## Testing Decisions

以下为计划，尚未执行，不引用旧候选结果为本次通过证据。

| 验收项 | 预期结果与证据 |
| --- | --- |
| 空环境安装 | 隔离空卷完成构建、迁移、模型 / 索引准备、管理员创建及启动；记录候选与资产身份 |
| 真实浏览器闭环 | Windows 浏览器真实登录、问数、多轮追问、经营分析、历史、保存成果及 XLSX / PNG / PDF 导出；检查内容和授权，不仅检查 HTTP 返回 |
| 停止与重启 | 关闭终端不退出；停止再启动，以及目标环境重启后手动启动，账号 / 历史 / 成果可用，Seed 不重播 |
| 升级与兼容回滚 | 可复现版本对完成升级、兼容回滚及再次读取长期记录；不兼容回滚拒绝且数据保留 |
| 安全失败 | 缺失配置、端口冲突、资产指纹不匹配、迁移 / 启动失败给出可操作诊断，不输出 Secret，不重置数据 |
| 环境隔离 | 初始化、停止、升级及验收清理不改变开发和稳定环境之外的资源；只清理由身份确认的验收资源 |

适用软件测试验证命令、隔离、版本兼容与失败行为；容器集成验证真实初始化、权限和持久化；浏览器 / Business Acceptance 验证产品闭环。AI Evaluation 根据最终 Diff 对模型配置、Prompt、Retrieval、SQL Guard 与资产基线的影响决定复用或重跑；复用需说明适用性，历史报告保留原提交身份。完整 Evaluation 仍遵循既有统一身份和零失败门禁，不强制新建专用 Evaluation 数据库。

## Out of Scope

- 云服务器购买或开通、公网 / 局域网访问、域名 / HTTPS、镜像仓库发布。
- 真实生产数据接入 / 迁移、全离线 LLM、GPU、多 worker / 多副本、金丝雀发布。
- R7 的动态 readiness、全面监控告警、备份恢复、容量 / 延迟 / 可用性承诺。
- 自动降级数据库、破坏性迁移、所有历史版本任意回滚或零停机保证。
- 新业务范围、新认证体系、公众注册、行列级数据权限。

- 验证和 Code Review 覆盖最终候选及受影响边界，记录未执行项、限制与失败证据；不改写 R1–R5 历史验收身份。
