# Product V1 作品交付收尾短 Spec

## 目标

按已确认的产品 V1 最终阶段，将演示、架构说明、可复现评测和运行证据整理为统一、可复查的交付入口，并使当前路线图和运行文档反映已核实的状态。

已确认范围来源：`.scratch/chatbi-product-v1/spec.md` 中的 V1 目标与“演示、架构说明、可复现评测与运行证据”；`docs/roadmap.md` 中关于汇总阶段证据和提供可复现入口的说明。用户于本轮要求按顺序完成剩余任务，并在此之前完成了整机重启。

## 范围

- 将 2026-10-10 整台 Windows 电脑重启后的 Stable 恢复结果记录到 R7 Acceptance，并同步 Runbook / Roadmap 中仍写着“整机重启未验收”的当前描述。
- 将 R5 Linux 中文下载名修复更新为 PR #64 已合并（`6dfc208`，8/8 required CI），保留真实历史记录。
- 整理一个 V1 作品交付验收入口，链接现有演示、架构、运行手册、R1–R7 验收和正式评测入口；不复制原始本机报告或 Secret。
- 按 Runbook 的正式流程，在最终文档候选上运行单轮、多轮和经营分析三套 AI Evaluation，并校验报告身份。

## 验收

- 当前路线图、R7 Acceptance、Runbook 对 R5 修复和整机重启状态一致；带日期的历史事实不被改写。
- 作品交付入口能从一个位置定位演示方式、架构、可复现评测命令、运行证据和已知边界。
- 整机重启证据仅陈述实际观察：Windows / WSL 启动时间、Stable commit 与镜像身份、持久卷身份、关键记录数量、Sales Mart Seed / 行数、health/readiness、备份状态；不声称未执行的浏览器验收或模型请求通过。
- 正式评测报告绑定一个干净候选、RAG 版本及案例集身份；三套结果逐项记录，不能以历史报告冒称当前结果。
- Markdown 链接检查、`git diff --check` 和当前上下文 Review 通过；本次纯文档变更不新增软件测试。

## 验证与发布边界

使用仓库既有 `docs/runbook.md` 第 9.2 节正式评测流程，报告写入 ignored `reports/evaluation/`，不提交原始评测报告。默认只形成本地候选；Push、PR 和 Merge 仍遵守独立授权规则。
