# 登录失败计数并发保护短 Spec

## 目标
并发的错误登录请求不得覆盖彼此的失败次数更新，也不得使账号锁定晚于既有阈值。

## 行为与范围
- 共享认证服务在处理单个账号的登录时，基于事务内最新账号状态作出是否允许登录、是否累计失败及是否锁定的决定。
- 同一账号的并发登录按 PostgreSQL 用户行锁串行；达到现有 5 次失败阈值时锁定 15 分钟。不同账号不共享该锁。
- 成功登录仍重置失败计数和锁定状态；锁定期间登录继续失败；审计、计数和 Session 的现有事务语义保持一致。
- 不改变认证 API、锁定阈值 / 时长、Schema 或用户可见的失败响应。

## 验收与验证
- 真实 PostgreSQL 并发测试：账号失败次数从 3 开始，两次并发错误登录最终计数为 5 并进入锁定；锁定期内正确密码也被拒绝。
- 定向认证测试、隔离 PostgreSQL development profile、全量软件测试及质量检查通过。
