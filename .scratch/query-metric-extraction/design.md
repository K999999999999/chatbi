# 指标原话提取的实施设计

依据：[已确认 Spec](spec.md)。本设计只落实其既有行为，不增加候选选择模型、别名目录或查询入口。

## 解析候选与认证身份

解析候选及其可观测评测结果保留客户说法；结构校验仍不等于指标身份认证。单轮、多轮 delta、历史首轮及历史修订提示词统一遵守此规则，排序及聚合指标引用不能继续要求模型提前输出规范名。未修改槽位继续继承，词汇表仍可用于已有澄清判断。

现有 `OnlineRetriever` 继续消费候选指标，按每项进行向量检索及名称 / 别名唯一确认。确认后的 `metric_constraints` 含请求说法、文档身份和权威指标名，`semantic_facts` 提供本次发布事实。复用这些数据完成 SQL 前的身份一致化，不为此增加第二次检索、不把静态词汇表当成认证事实。

在 Online Query 既有认证代码附近收敛指标身份和指标引用处理，使用普通函数及已有 DTO。必要的纯名称比较逻辑以传入候选数据为输入，与 Retrieval 已有比较语义一致；不引入 Service / Port / 全局缓存，不复制另一套在线别名事实。

认证只接受本次已选指标；检索上下文中用于血缘或其他用途的额外 Metric 不能变成用户请求指标。零匹配、多匹配、候选缺失、指向未选指标以及认证后重复的条件都须拒绝，不能以排名、SQL 或模型猜测补齐。去重及顺序遵守现有请求规划规则。

普通在线问数在 SQL Prompt 组装前使用本次已认证的指标身份；完整历史 profile 在 `prepare_restoration_state` 中同时规范指标、排序目标和聚合筛选目标，然后保存既有格式的状态。静态评测及经营分析内部既有规范身份调用保持各自 Contract，不强迫无认证上下文的路径采用伪造认证。

## 历史修订的先后顺序

`semantic_revision` 当前在检索前直接比较指标字符串。保留结构合法性、明确 keep/set/clear、数量及维度等不依赖指标身份的判断；将依赖“是否同一个指标”的成员检查推迟至本轮已有发布上下文可认证时。

复用现有条件即可携带尚待认证的指标说法，不新增持久状态字段：

- 单一指标真正替换时，既有唯一指标排序继承规则可将排序目标指向新的候选说法，最终由认证确认；多个指标时，保留待认证目标，不能按数组位置强行替换。
- 继承的聚合筛选保持原目标。新旧只是同指标不同别名时，认证后目标相同；真正更换指标导致旧聚合条件不再对应所选指标时，继续要求澄清，不能自动改成新指标条件。
- 认证后的排序和聚合目标必须属于已选指标；同指标多种说法不会造成错误的“指标已变化”。

业务条件引用不明确使用局部可区分的业务异常，执行层将其转成已有 `CLARIFICATION_REQUIRED`，保留原有语义修订失败类别，不生成 SQL、不执行数据库、不提交成功状态。认证数据故障仍为 `CONTEXT_ERROR`。METRIC 检索自身未命中或歧义仍沿用现有 `CANNOT_ANSWER`；不能将技术故障或所有认证失败一概改成澄清。

认证检查虽在获得上下文后完成，业务语义修订失败仍采用现有语义失败归属；Trace 应保留实际认证检查位置，不伪造第二次模型解析。

## 备选方案与取舍

| 方案 | 结果与成本 |
| --- | --- |
| 仅修改提示词 | 首轮简单别名可能可用；历史排序、聚合筛选及多指标身份检查仍按字符串错误拒绝，不满足 Spec。 |
| 修订前再次加载静态词表或额外检索来提前规范化 | 增加在线业务真相副本或重复检索及资产版本竞态；还会使候选原话在既有检索前再次被替换。 |
| 复用本轮检索后的认证，统一检查指标及引用 | 选用；没有额外模型或查询，保护原话候选与规范状态之间的现有边界。需要调整已有字符串检查的执行位置及业务错误分类。 |

Owner 为当前工作项实施负责人。只有将来明确要求未登记口语的自动语义选型、指标选择模型或新状态格式时，才重新评估本设计；本次不建设这些能力。

## 兼容、回滚与验证

状态版本、持久化表及快照格式不变；保存的指标与条件仍为规范身份。旧快照按当前相关发布事实认证；不重写旧原问题、旧时间及结果。无数据迁移、Feature Flag 或分阶段生产部署。

解析、修订及认证应作为一个原子候选交付，避免只发布提示词导致已有续聊失效。未部署前可放弃候选；部署后如需回滚，使用完整代码版本回滚，已保存的规范状态继续兼容；不以关闭 Guard 或修改历史数据恢复。

确定性验证覆盖原话传递到检索、名称比较一致性、引用归一化、同指标别名修订、真实指标替换、非法 / 模糊输入、失败零 SQL / 零 DB 调用及状态不推进。真实模型行为独立评测：旧六字段用例兼容，并按需扩展评测案例类型支持受控澄清与修订模式；不能将业务澄清结果当成 Provider 故障或篡改旧案例期望。历史条件另走完整历史 profile 及正式网页入口，不能用六字段评测代替。
