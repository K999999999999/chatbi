# ChatBI 产品 V1：已确认目标与待澄清范围

## 已确认目标

用户于 2026-10-03 在本轮对话确认以下目标：把 ChatBI 做成面向销售经营分析的完整 AI 数据产品作品；用户通过对话获得可信的数据、图表和分析报告，开发者能够独立部署、维护并核验正确性与运行能力。

产品目标包含独立 Web 前端、连续对话、图表、流式反馈、历史记录、成果保存与导出，以及部署和运行证据。第一版聚焦销售领域及单一 PostgreSQL 数据源；SQLBot 作为交互与产品完整度的参照。多数据库、多租户及仪表板编辑器属于后续按真实需求评估的扩展。

## 已确认的阶段路线

1. 明确产品 V1 的用户、核心场景、支持与不支持的行为和验收标准。
2. 完成用户闭环：独立 Web 前端、对话、图表、流式反馈、历史和成果保存。
3. 完成生产准备：目标环境部署、安全检查、监控、容量与恢复验收。
4. 整理作品交付：演示、架构说明、可复现评测与运行证据。

此顺序是阶段路线；用户在项目审查后进一步授权修订需求层优先级，见下节与 `docs/roadmap.md`。实现切片、直接依赖和技术选择待行为澄清及设计审查后确定。部署约束和安全边界在相关设计前澄清，不推迟到功能完成后才考虑。

## R1 逐项确认结果

- 仅电脑端，不加入手机适配 / 手机验收；采用 React + TypeScript + Vite，复用 FastAPI。
- 同页手动切换问数 / 经营分析，默认问数，展示和状态分开；分析不继承普通查询条件。
- 单台 Linux / 云服务器供指定账号使用，保留本地开发；不开放公众自助注册。
- 浏览器使用 HttpOnly Cookie，沿用数据库 Session 期限；同源访问、线上 HTTPS、CSRF 防护，并保留 Bearer 兼容。
- 刷新保持登录，但 R1 阶段进入空白新对话；R3 实现按账号保存到后端数据库的长期历史与重开，保留 / 删除 / 续聊待 R3 细化。
- 有查询权限的指定用户共享同一套业务数据，个人历史按归属隔离；首版不新增区域 / 部门数据隔离。
- 等待时禁用再次发送、模式切换与新对话，仍能编辑草稿、查看既有结果及退出；详细进度 / 取消由 R4 处理。
- 前端不自动重发问题。明确失败保留上一成功状态；结果未确认时普通问数提示新开对话、补全问题，经营分析使用原任务 ID / 原问题手动重试。
- 迁移期间保留 Streamlit；新前端覆盖核心功能并通过验收后移除，不长期维护双入口。
