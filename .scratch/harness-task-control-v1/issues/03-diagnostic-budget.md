### What to build

按问题ID记录原因假设、动作、结果、有效证据、无进展轮数及有界等待；提供预算查看、诊断推进和升级结果，触发后拒绝继续诊断转换，允许只读 / 证据保存 / 用户决定登记。

### Acceptance criteria

- 第3轮连续无进展或累计有效诊断时长1800秒任一触发；边界前不误触发。
- 重复证据、重复命令、问题改名、重开会话不会获得新预算；有实质证据的更新保留可核实来源。
- 正常等待 / 暂停有起止和理由，超时、时钟倒退或无法核实返回待核实，不能无限延长。
- 升级报告说明可靠候选、累计改动、失败、尝试、未知和下一步成本；不自动撤销改动或杀进程。

owned files: Plugin工具诊断/预算部分、CLI、`tests/test_harness_budget.py`、预算及交接文档。

Verification evidence: 可控时钟与边界值；跨进程重读、问题别名、坏时间区间、重复证据及重开记录回归；无真实30分钟等待。

Migration / Rollback: 缺失旧计时明确未知，不补造零预算；回退保留问题记录，不能用降级清零。

Done When: 所有预算与恢复边界测试通过，工具限制明确；阶段推进失败时状态一致。

Result: Done。新增跨会话 `diagnostic` CLI 与版本化预算记录，按稳定 problem-id / 显式别名持续保存原因、动作、结果、证据、等待、用户决定和累计时间。连续3轮无进展或连续有效诊断1800秒任一触发后，状态 / 升级报告继续可读，证据可继续登记，后续诊断写入被拒；用户明确继续会开启新一段有界预算并保留历史。等待最多3600秒；逾期、时钟倒退或不可核实区间进入 needs_review。升级报告含当前候选完整度、累计 / 本轮 Diff、尝试 / 失败、未知和下一步成本；工具不杀进程、不回滚。验证：Python 3.11.16 ChatBI 容器及 Python 3.14.4 本机各运行完整Plugin unittest 27项 PASS；覆盖3轮 / 1800秒边界、重复证据与命令、重复 ID / 标题 / 别名、等待边界 / 超时、时钟回拨、跨进程重读、停止 / 继续决定及Secret样式输入拒绝；`py_compile`、CLI帮助和 `git diff --check` PASS。没有真实等待30分钟或网络调用。
