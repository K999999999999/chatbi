# Harness V1 实现设计

本设计落实[已确认 Spec](spec.md)与[设计审查](design-review.md)的四项约束，不另定义业务 Contract。Owner 为当前主 Agent；改变 Spec 范围、运行边界或授权方式时返回需求 / 设计确认。

## 边界与运行

通用工具随 engineering-workflow Plugin 分发，使用 Python 3.11 标准库和已有 Git 命令；无 pip 安装、业务应用依赖、网络服务或后台线程。项目 adapter 为可校验的数据，指定仓库身份、主分支、记录位置、阶段规则、风险路径、文档职责和适用验证，不加载项目提供的 Python 代码。

只读命令不执行 adapter 中的任意 shell 命令，不安装依赖，不读 .env，不访问业务服务。验证命令由 Agent 在项目规则内另行执行，工具核实安全报告及其适用身份，不成为任意命令执行器。

GitHub 读取 / 配置使用已有授权工具，由阶段 Skill 协调；核心工具接收有采集时间、仓库 / head / base / 来源的安全结构化快照并校验相容性。缓存和 Mock 不能冒充实时远端核验。配置动作由 Agent 在明确授权后执行并读回，不在只读检查中隐式发生。

ChatBI 提供容器内薄入口；通用代码只读挂载，状态读取时 common-dir 只读，明确写命令时仅授权状态位置可写，源码挂载只读；不挂载 Docker socket、不转发 .env。显式指定经核实的 Plugin 根路径，默认可按已支持的环境发现方式解析；不硬编码机器路径，也不因源可读就声称安装已更新。帮助和旧只读入口不因未安装新版工具而误报新版通过。

## 状态与原子写入

当前状态仍在项目适配指定的单个 Markdown 文件中；ChatBI 继续使用 Git common-dir 下同 ID 的 status.md。顶层旧字段为其已有语义的唯一权威；版本化 JSON 扩展代码块只保存运行情况、结构化依据、诊断问题 / 等待、转换与修订信息等新数据，不复制旧字段形成另一真相。

查询必须验证字段重复、扩展版本、引用和相容性，输出文本及结构化 JSON。未接入 adapter、旧记录或未知版本明确标记；只读命令不进行自动迁移。显式迁移保留旧内容 / 原件和来源，不补造历史批准、验证或预算。

写入以一个语义命令完成读最新版本、获取工作项互斥、核对预期整文件摘要、检查转换、准备完整文件、同目录原子替换。版本冲突 / 锁占用 / 保存失败非零退出且不写成功。遗留锁不按时间自动删除；恢复核实锁归属与原记录后再显式处理。不是对外部手工编辑的强制锁。

单 writer、原子快照与版本检查优于引入数据库 / 事件服务；另建可写 JSON 当前状态会增加双写故障。历史事件 / 备份只提供来源，不参与竞争当前权威。未来出现真实多用户服务需求才重新审查存储方案。

## 阶段、依据和授权

阶段与运行情况独立：等待用户并不把整个目标自动标 blocked；暂停须有用户依据。阶段规则按 adapter 的闭集定义，校验支持的小任务捷径与回到修复阶段的条件，未知阶段不自动放行。

依据具有类型、来源、仓库、候选 / base或其他输入身份、覆盖、采集时间和核实方式。核实方式区分 machine-verified、attested、unverified。人工决定 / 语义判断可使用带来源的声明；Git身份、测试报告、远端合并事实等可核实项必须核对其内容与身份，缺失或不可读不当通过。

范围授权和候选批准分开存；用户确认Spec / Ticket不自动变成实施或发布授权。候选实质变化后旧批准不冒充新批准，同范围CI修复在持续授权内仍须刷新Diff / 验证，不改变关键决定时不另设逐Commit审批。

新工具能阻断经过它的错误转换，不能证明 Agent 未绕行、声明必真或真实运行已强制停止。不得把回填字段当成运行历史。

## Diff 与证据失效

任务起点、上次切片和当前候选分别绑定Git身份；包含commit、index、worktree及未跟踪变化的安全清单。默认展示路径 / 状态 / 统计 / 引用，不自动输出敏感文件内容；忽略 / 敏感配置不因“完整Diff”被读取输出。完整性边界与未纳入范围须说明，不能只统计已提交改动。

确定性路径分类识别敏感区域，语义变化由Agent Review补充；没有声称自动理解所有Diff。分类规则本身变更视为高风险。源码、base及输入版本变化按覆盖使证据失效或进入需声明理由的复核，保留原报告身份。报告可读与代码相容分开判断。

## 预算与交接

按稳定问题ID保存无进展轮数、有效证据和计时起点；进展引用必须存在且不同于已计证据。相同证据或无依据文字不能清零。问题别名显式指向原ID，不创建同问题的新预算。

有效诊断时间为记录区间减去有界正常等待及显式暂停，等待须记录原因、起点和截止；长命令 / CI 超时或未知时间返回待核实而非无限豁免。跨会话保留起点；无法核实时不推定恢复为零。第3轮无进展或累计1800秒触发升级，工具拒绝继续诊断转换；只读查看、证据保存及用户决定的记录仍可进行。

升级输出包含本轮 / 累计改动、可靠候选、失败证据、假设 / 尝试、未知及建议成本。执行中的进程是否停止仍由Agent / 工具调用生命周期处理，没有后台监控保证。

## 接入、维护与迁移

初始化分发现、差异计划、已确认文件的本地写入、另行授权的远端应用 / 读回四步；重复运行不覆盖已有机制或生成空绿色job。发现不到真实验证命令时输出待确认，不猜测语言 / 框架。setup Skill 的现有“仅本地规则”说明需在已确认范围内更新，保持安装不触发初始化。

动态文件清单由项目维护；工具检查引用、适用结论、依据及声明完整性，语义Review单独记录。持续维护沿用现有Harness复盘 / follow-up：缺口未验证效果前不关闭；指标只记录实际可取得数据，不导入遥测服务。

旧工具保留其原检查行为与退出码；新版接入不可达时报明边界，不降级后宣称新版门禁通过。CI通过容器挂载仓库内合成Plugin fixture验证ChatBI adapter；通用工具自己的测试在Plugin仓库维护，不依赖开发机的安装路径。真实安装同步与当前会话加载另列交付，不由fixture通过推断。

本目标在新工具实现 / 安装之前继续由现有工作记录管理；不要求尚未交付的工具反过来证明自身开发历史，也不把手动维护记录说成新版试运行结果。

## 验证与交付

标准库测试使用临时Git仓库、合成状态与可控时间，验证行为和拒绝路径；ChatBI adapter测试覆盖容器挂载、旧命令兼容、无Plugin路径、只读 / 写边界与来源身份。必要的静态文档检查继续复用项目入口。

远端严格base与实际阻断验证分离：本地先准备可审查计划、旧配置快照与回退说明；未授权不修改真实Ruleset或创建实验PR。两仓库各自形成候选、Review和发布说明；源变更不等于安装生效，缺权限不等于无保护。无远端授权时完成本地候选范围并准确报告待交付，不宣称整个远端目标已完成。
