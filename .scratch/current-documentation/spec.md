## 问题与目标

当前项目文档混合了现行行为、开发方案、实施进度与历史验收。部分 Spec 仍写“尚未发布”；在线检索和多指标文档明确标为历史，却将当前唯一契约指向 `.scratch/`。README 与项目导航重复承担阅读入口。Runbook 混用数字章节、未编号标题和开发阶段，正文用章节符号引用，后续能力不断追加到末尾。

目标是让读者从 README 找到当前项目的能力、结构、行为、操作与验证方式；从 AGENTS.md 找到当前协作规则。工程过程可在 `.scratch/` 追溯，当前正式文档不再靠拼接历史记录才能理解。通过项目规则、确定性检查和现有 Review 共同维护这一状态。

Change Profile: 跨文档、Agent 规则和 CI 检查的工程维护；不改变产品行为、架构依赖、授权、安全策略、数据库或运行配置。采用完整 Spec 与设计审查；实施拆分及发布遵守现有仓库流程。

## 用户场景

1. 新读者从 README 知道产品是什么，定位模块、当前规则和推荐运行入口，不必在两个导航入口之间跳转。
2. 维护者查看功能 Spec 就能知道当前有效行为；历史资料仅用于追溯，不能反向覆盖已确认规则。
3. 后续 Agent 从 AGENTS.md 发现归属和维护要求，按改变的内容更新正确文档并归档过程。
4. 提交者在本地发现结构与链接违规；CI 使用相同规则，确定性违规使现有检查失败。

## 当前文档行为

### 归属与唯一事实源

- 每个主题的权威规则集中维护。导航和其他文档链接它，不再复制完整定义形成竞争副本。
- 已交付功能的当前行为固化在正式 Spec；不能继续把 `.scratch/` 的历史规划作为当前唯一 Contract。
- 当前工作在确认、实施过程中仍可使用 `.scratch/` 保存 Spec / Design / Ticket；交付时整理现行规则，规划来源标明其历史用途。
- 现有已确认 Contract、后续扩展和兼容边界是迁移依据。代码和测试用于核对实现与证据，不用旧实现改写已确认规则。
- 发现没有权威证据可裁定的行为矛盾，记录具体冲突及影响后提出必要澄清；不能在文档整理中自行选择新行为。
- `.scratch/` 的历史、ignored 报告、本机 Git 公共目录实时状态各保留现有职责，不复制 Secret 或混合候选身份。

### 阅读与结构

- 开头简明说明用途、适用对象和阅读入口；短文档不机械添加模板章节。
- 按当前能力、模块或操作组织，开发阶段编号不再作为主要阅读目录。必要的版本、案例或来源标识仍可保留。
- 标题层级连续，同层标题表达相同层次。段落围绕一个主题；步骤用编号，比较用表格，复杂关系按需使用图示。
- 正文引用使用可点击的文档名 / 章节名，替换原有章节符号和裸数字跳转；术语首次出现时提供必要解释。
- 后续修改融入对应章节；旧方案、实施阶段、候选失败和复验过程进入工作记录，避免追加整段开发日志。
- 减少重复与不必要的长段落，不以固定字数、文件数或所有文档统一模板代替阅读判断。

### 历史迁移

- 归档首先检查对应工作记录已有内容；完整覆盖时引用现有记录，不为满足目录形式再造副本。
- 独有的决定理由、取舍、候选身份与验收证据必须保留。需要完整归档原文时保存在所属 `.scratch/<work-item>/history/`；所属不明时在本工作项历史区保存并说明来源，不编造旧授权或工作项。
- 移动 Markdown 后修复相对路径和必要章节链接，保留文档原候选、日期、环境和结论。路径修复不改变历史验收结果。
- 被移除文档的引用必须逐项迁移：当前入口指向当前说明，历史引用指向归档资料，不能全部粗暴替换为同一个新文件。
- 本次迁移记录原位置、目标位置、保留的独有内容和验证结果。已有历史记录不批量重写成当前状态。
- project-guide 的导航价值并入 README 后移除独立入口；细节归入所属文档，README 不直接接收整份长文。

## 持续维护与防复发

### 规则入口

AGENTS.md 保留简短强制入口；`docs/agents/` 集中维护文档归属、更新触发条件、历史保存和交付核对要求。精简现有重复说明，保持任务恢复、授权、发布、Auto-merge 与 PR 收尾等现行规则完整。

功能或配置变化时，作者需记录更新了哪份当前文档、历史过程记录在哪里，或说明不适用理由。纳入现有 Done When、Agent Review 与 PR 记录，不新增用户 Review 阶段，不为每次改动强制新增文档。

### 确定性门禁

沿用现有 Markdown 链接检查；补充轻量文档结构检查，接入现有 CI 的 Deterministic tests job，不新增依赖、LLM 语义审查或必需检查名称。具体脚本组织由设计审查确定，本地与 CI 必须使用同一入口及规则。

| 检查 | 覆盖范围 | 结果 |
| --- | --- | --- |
| 本地 Markdown 目标与章节链接 | 沿用现有 tracked / untracked 非 ignored Markdown 检查范围，包括迁移后的工作记录 | 不存在的文件、失效章节或越界目标导致非零退出。 |
| 标题层级跳跃 | 当前 README、AGENTS、领域入口和 docs 下的正式 Markdown | 从已有父层直接跳过一级标题时报文件及行号，非零退出。 |
| 章节符号引用 | 同上，正文中的章节符号加章节编号引用 | 非零退出，提示改成具名章节链接。 |

结构检查不约束 `.scratch/`、原始 reports、Git 公共目录或历史快照的写作风格。代码块、行内代码以及明确的说明性字面量不作为正文违规；不能因示例 Markdown 标题或用于说明规则的代码片段误报。历史文件仍受本地链接检查保护。

检查只做可靠的确定性判断。旧目录引用随原文件迁移后由链接检查发现；不引入文档数量上限、字数硬阈值、开发阶段词汇一律禁用，或用关键词推断业务语义冲突。

CI 文件接入可使对应 job 在违规时失败；远端 required checks 配置只有在发布获授权并实际核实时才宣称已具备合并阻断效果。本目标不默认授权远端配置修改。

### 现有 Review

Review 核对归属、现行规则完整性、竞争副本、历史混入、章节组织、导航可达性与命令适用范围。交付记录给出受影响文档和核对结论；脚本成功不能单独证明内容准确或可读。防复发采用规则、检查和 Review 三层，不承诺语义问题永远零复发。

## 验证与验收

1. 为门禁建立有意义的坏例子回归：标题跳级、正文章节符号引用、断链 / 失效锚点均失败，输出定位到对应文件与行；代码块、行内代码、历史目录和正常链接不误报。
2. 验证本地入口与 CI 调用同一检查；临时目录 fixture 无违规退出 0，有违规非零。测试不依赖真实 LLM、数据库或公网。
3. 对最终文档运行全库本地链接检查、正式文档结构检查、受影响 Python 检查器回归与 Python 质量检查、Harness 本机检查及 Diff 检查。记录候选 / 基线和覆盖范围；实施改变后重跑受影响项。
4. 对照迁移清单检查当前规则有对应位置，独有历史依据完整保存；所有现行正式文档摆脱历史规划作为唯一 Contract 的情况。
5. 进行阅读走查：从 README 定位产品、结构、核心能力、测试与运行；从 Runbook 选择容器开发 / 宿主调试 / Stable；从 AGENTS 定位规则和检查入口。按当前代码与已确认 Contract 核对指向，不运行具有业务或运行副作用的命令来证明文档已整理。
6. 保存本次迁移、验证和 Review 证据于本工作记录；检查 Roadmap 是否受完成事实影响，记录更新位置或不适用理由。新目标不改变产品优先级或补造公网生产就绪结论。
7. 本目标不改变业务代码、模型或案例；不把历史软件或 AI 评测结果称为当前候选新结果。确需进一步运行验收时明确用途与授权范围。
