## Problem Statement

当前 Compose 只管理 PostgreSQL、Qdrant 和保留的 Dev Container；FastAPI 与 Vite 仍由开发者分别在本机启动。默认 API 命令未启用自动重载，新环境还需安装 Python、uv 和 Node。目标是在 R2 开发前统一开发入口，减少重复启动与本机依赖配置，并为后续 R6 打包积累可复现的运行基础。

事实源：[Runbook](../../docs/runbook.md)、[Compose](../../docker-compose.yml)、[Bootstrap Contract](../../docs/specs/bootstrap.md)、[Web Contract](../../docs/specs/web-dialogue-v1.md)、[Architecture](../../docs/architecture.md)、[路线图](../../docs/roadmap.md)。当前仓库状态不等于新容器入口已通过验收。

## Solution 与范围

- 在 WSL / Linux 上，以 Git、Docker Engine / Compose 和系统 Shell 为宿主工具前提。推荐入口不要求本机安装 Python、uv 或 Node。
- Compose 统一管理 FastAPI、Vite、PostgreSQL 与 Qdrant。前后端依赖安装及显式初始化均在容器中完成。
- 提供统一启动、停止、状态查询和日志入口；具体命令命名在设计阶段确定。
- 前后端使用开发运行环境：挂载源码，后端自动重载，前端 Vite 热更新。修改应用源码无需重新构建依赖镜像；依赖清单变化按文档显式更新安装或构建。
- 推荐容器入口，保留 WSL / Linux 本机运行方式用于调试，两种方式共享现有业务 Contract。使用相同端口时不同时启动两套应用。
- 此目标属于 R2 前的开发环境准备，不完成 R6 的正式部署验收，不改变 R2–R5 产品交付顺序。

## User Stories

1. 新开发者复制安全配置模板、填入本地配置后，可通过容器命令安装依赖和完成首次初始化，无需安装本机语言运行时。
2. 已初始化的开发者通过一条命令后台启动整个开发应用，打开固定本机网页地址登录、问数与追问；终端关闭不会停止应用。
3. 修改后端 Python 源码后自动重载，修改前端源码后浏览器获得 Vite 更新；可查看服务状态和日志定位失败。
4. 停止再启动后，业务数据、账号、数据库 Session、checkpoint、模型缓存和已发布索引按既有生命周期保留；临时多轮会话不承诺保留。

## Observable Behavior

### 日常启停与访问

- 统一启动负责服务构建 / 启动及必要的运行状态检查；返回失败时以非零退出码和安全诊断指出阶段，不报告整个环境已成功运行。
- 前后端没有电脑或 Docker 重启后的自动启动策略。显式启动后后台运行，显式停止后保持停止。
- PostgreSQL 与 Qdrant 保留现有 `unless-stopped` 策略；统一停止包含本目标管理的四个服务，不删除持久数据。
- 宿主发布端口仅绑定 `127.0.0.1`；浏览器默认访问 `http://127.0.0.1:5173`，API 默认 `127.0.0.1:8000`，数据库与 Qdrant 沿用已有端口。
- 容器通过内部网络连接依赖；浏览器使用相对 URL 和 Vite 代理访问 API，沿用 Cookie、CSRF 和 Origin 校验，不向前端注入 LLM / 数据库凭据。
- 状态和日志能区分服务未运行、启动失败与 HTTP 存活。现有 `/health` 不扩展为下游动态 readiness；环境启动成功不等于真实查询验证通过。

### 首次初始化与失败恢复

- 首次初始化保持四类显式操作：`migrate`、`create-admin`、`prepare-model`、`build-rag`，复用 `python -m src.bootstrap`。启动不隐式执行这些操作。
- PostgreSQL 首先完成基础初始化，随后显式 migration 安装 checkpoint 等对象，最后才等待完整 healthy；不得因 migration 尚未执行形成无法进入初始化的健康等待循环。
- 管理员密码沿用交互隐藏输入与确认，保持现有重复创建的拒绝行为；迁移账号不进入常驻 API 运行环境。
- 配置缺失、端口占用、依赖不可连接或安装 / 构建失败时，给出可定位提示及非零结果。日常恢复通过修正配置 / 依赖后重试，不自动重置数据或创建身份。
- 缺少模型或索引时按既有 Bootstrap / RAG Contract 在启动或首次使用阶段暴露失败；不增加开发环境强制预加载，不绕过 fail-closed 行为。

### 源码更新与状态

- 后端使用单应用 worker 的开发自动重载，保持现有多轮会话可见性约束；不引入多副本或共享状态存储。
- 自动重载及停止重启会清空进程内多轮会话。文档说明重新开始对话，网页遵循现有失联 / 会话失效 Contract。
- 前端更新使用 Vite 热更新；不承诺刷新或任意更新后保留页面状态，沿用 R1 刷新进入空白对话的行为。
- 环境配置、依赖或非源码资产变化的应用方式由设计明确并写入 Runbook；不将所有文件变化都承诺为自动重载。

## Implementation Decisions 与不变量

- 本地 Embedding 显式默认 CPU，不承诺 GPU。远端 LLM 继续使用开发者已有配置和真实服务。
- Python、uv、Node 与应用依赖使用明确版本及仓库锁文件；容器与宿主虚拟环境 / Node 依赖隔离，避免源码挂载覆盖容器已安装依赖。
- 数据库和 Qdrant 保留现有项目 named volume；已有 `.model-cache/` 与 `data/rag/` 内容可复用，启停不重复下载、播种或重建。具体缓存挂载与所有权方案由设计决定。
- API 与显式初始化工具按操作取得所需配置；保留外部环境变量优先于 `.env` 的既有约定。不得因为挂载整个仓库而让迁移身份进入 API 运行环境。
- Secret 不进入源码、镜像构建上下文 / 镜像层、Git、日志或报告；不修改用户现有 `.env`。源码挂载和文件权限需保证宿主能正常编辑生成文件。
- 不改变 Architecture 的模块职责、查询链路、业务语义、SQL Guard、认证授权、数据库对象或 RAG 发布规则；容器网络地址变化属于运行适配。

## Testing Decisions 与验收

| 场景 | 可观察通过条件 | 证据 |
| --- | --- | --- |
| 新环境准备 | 不使用宿主 Python / uv / Node；容器内完成依赖安装、基础初始化、migration 与管理员创建，API 和网页可运行 | 独立临时 Compose 项目 / 数据卷运行记录 |
| 模型 / 索引入口 | 容器命令能复用或显式准备固定模型，按既有 builder 构建并发布索引；已有缓存与资产可读 | 模型和 RAG 身份、命令结果；复用已有行为证据的适用理由 |
| 日常启动 | 一条命令启动四个服务，关闭启动终端后继续运行；浏览器地址可访问，状态 / 日志可查看 | 实际服务状态、HTTP / 浏览器记录 |
| 热更新 | 后端源码修改触发重载；前端源码修改在浏览器中生效；不靠重建镜像实现普通源码更新 | 安全且可恢复的变更演示和进程 / 浏览器证据 |
| 停止 / 重启 | 显式停止后服务保持停止；再次启动复用持久数据和缓存，多轮会话按进程生命周期失效 | 前后数据 / 资产身份核对与状态记录 |
| 故障 | 缺少必要配置、依赖故障及首次 migration 未完成可识别，失败不报告全部成功，不清空数据 | 确定性检查及隔离运行场景 |
| 本机边界 | 四个服务的宿主发布端口仅回环绑定，网页 Cookie / CSRF 及代理正常 | Compose 解析、端口检查和浏览器验证 |
| 真实链路 | 浏览器登录 → 成功问数 → 同一对话追问，结果与独立参考符合选定场景 | 真实 LLM / 模型 / 索引 / 开发库报告 |

用户已允许少量真实 API 调用费用。首次初始化使用独立临时数据卷，保护当前开发数据；真实链路复用现有资源及账号流程，不改动已有用户身份与权限。需专用验收账号时沿用现有隔离与清理办法。

按风险选择配置 / 命令行为测试、针对性软件回归和实际容器运行验收。只对有实际契约价值的确定性行为补测试；不为纯包装逐行复制实现。当前不重跑全套 AI Evaluation，也不把少量浏览器场景声明为新正式三套基线。

所有最终证据关联候选提交、配置范围、镜像 / 锁文件及资源身份；CPU 构建索引的实际耗时记录为测量结果，不预先承诺性能指标。规划阶段不运行真实调用、模型下载或数据初始化。
