# ADR-0001：Multi-Turn Query V1 的会话与状态边界

- 状态：Accepted（已接受）
- 日期：2026-09-18
- 范围：ChatBI Multi-Turn Conversation V1

## 背景

当前 ChatBI 已经具备单轮自然语言查询、Online Retrieval、SQL Guard、数据库执行、授权和 Trace 能力。下一步需要支持用户在上一轮查询结果的基础上继续追问，但不应在没有明确边界的情况下直接扩展成长期聊天、复杂分析 Agent 或多查询编排。

多轮能力还会引入新的状态和安全风险：会话可能被错误用户访问，失败的追问可能污染后续状态，历史状态可能被误当作当前授权，客户端也可能提交未经验证的指标、SQL 或数据范围。

## 决策

### 1. V1 是单条查询的结构化修订

V1 只允许在同一条 `SemanticQuery` 语义范围内新增或替换指标、维度、时间范围和过滤条件，然后重新执行一次查询。

V1 不包含：

- 同比、环比和多时间段比较；
- 趋势判断和原因分析；
- 自动拆解为多条查询；
- 多查询结果汇总；
- 长期记忆和自主 Agent 规划。

这些能力留给后续独立的 `Business Analysis V1` Feature。

### 2. 会话属于当前认证用户

每个会话只能由创建它的当前认证用户继续。客户端不能通过提交 `subject`、角色、数据范围或完整状态来改变会话归属或授权结果。

每一轮都必须重新使用当前认证身份和授权策略；会话状态不能替代授权，也不能把上一轮的授权结果延续为永久权限。

### 3. 只保留最后一次成功查询的结构化状态

服务端状态只表达最后一次成功查询的指标、时间范围、维度和过滤条件，不把原始对话、候选 SQL、最终 SQL 或结果行作为多轮状态保存。

失败轮次不提交新的状态，后续追问继续基于最后一次成功状态。合法但为空的结果视为成功状态，可以成为下一轮基础。首轮失败不创建会话，也不返回新的会话编号。

### 4. 会话是短期当前会话

V1 只保证当前会话内连续追问，不保证页面关闭、会话过期或服务重启后的历史恢复。Streamlit 只维护一个当前会话，并提供“新建会话”操作，不建设会话历史管理。

会话使用 30 分钟无成功状态更新的 Idle TTL。服务端同一时间只允许一个轮次进入同一会话；并发轮次返回 `CONVERSATION_CONFLICT`，不进入下游查询、不提交状态。

### 5. 保持现有 Query API 的向后兼容

继续使用现有 `POST /api/v1/query` 入口。`conversation_id` 是可选的：缺少时按无状态首轮执行，首轮成功后创建新会话，存在时继续该会话。只提交 `question` 的旧调用仍然按单轮查询运行。服务端生成并返回 `conversation_id`，客户端不提交完整会话状态。

未知、过期或不属于当前用户的会话统一返回 `CONVERSATION_UNAVAILABLE`（HTTP `404`），避免暴露会话是否存在。歧义、范围外分析和并发冲突分别使用 `CLARIFICATION_REQUIRED`（`422`）、`UNSUPPORTED_ANALYSIS`（`422`）和 `CONVERSATION_CONFLICT`（`409`）。

### 6. API 和现有 Streamlit Reference Client 同步支持

多轮能力同时在 Query API 和现有 Streamlit 页面提供。该决定不建设正式 Web 前端，也不引入第二条查询链路。

### 7. 交付边界

本 ADR 记录的是带生产安全约束的内部或受控用户 V1，不宣称已经完成面向所有企业用户的最终 Production Ready。真实企业 SSO、持久化审计、长期会话、负载治理、正式部署和回滚仍需独立的生产化工作和验收。

## 取舍与后果

### 正面影响

- 复用现有 Online Query 和授权链路，避免建设第二套查询逻辑；
- 状态范围小，容易进行确定性验证和失败回滚；
- 不把原始业务数据和 SQL 隐式变成长期记忆；
- 为后续 Business Analysis 保留清晰的状态、权限和资源边界。

### 代价

- 用户暂时不能恢复历史会话；
- 不能直接完成同比、趋势、原因分析等复杂问题；
- Streamlit 只能管理一个当前会话；
- 正式企业生产仍需要单独补齐身份、审计、部署和运行治理能力。

## 验收方向

- 通过确定性测试验证正常三轮场景、状态替换/叠加、失败不提交、空结果、用户隔离、逐轮授权、歧义澄清、范围拒绝和旧 API 兼容；
- 通过 Streamlit 验证当前会话追问和新建会话；
- 在获得单独运行授权后，通过真实三轮 E2E 验证真实 LLM、RAG、SQL Guard 和数据库链路。
