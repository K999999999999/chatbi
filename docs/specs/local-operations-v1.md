# R7 本机稳定环境运行保障 Spec

Status: 用户2026-10-08确认完整Contract和七项整体本地实施；实施中。本文定义目标行为，不代表所有能力已实现或已在稳定环境部署。

## Problem Statement

R6 已提供固定版本本机部署与兼容升级 / 回滚，但 `/health` 仅反映 HTTP 存活；稳定环境的阿里云链路输出当前关闭，备份恢复与持续依赖检查尚未提供完整 Contract。服务退出时，最后操作的部署状态记录不能独立证明当前可用性。

本轮目标是当前 Windows + WSL2 Linux x86_64 + Docker 电脑上的 `chatbi-stable`，主要自己日常使用与演示。`chatbi-engine` 继续用于开发测试；本目标不启停、覆盖或恢复开发数据。

Canonical Source: 本文件是已确认R7行为Contract；实现和验收进度见工作记录及Acceptance。既有未改变行为以原Spec为准。

事实源：[Roadmap](../roadmap.md)、[Architecture](../architecture.md)、[Product Scope](../product-scope.md)、[R6 Contract](../specs/local-deployment-v1.md)、[R4](../specs/execution-streaming-v1.md)、[R5](../specs/result-export-v1.md)、[Observability](../specs/observability.md)、[Web](../specs/web-dialogue-v1.md)。规划基线 master `0c77d80f35cde135160e4a8806f639397f1867ff`；稳定运行与原验收身份仍为 `2b4a8c8`，不改写历史报告身份。

## Solution / Scope

在既有 Application / Infrastructure / HTTP 与本机运维入口内补齐运行状态检查、统一业务执行保护、状态提示、加密在线备份、隔离恢复及诊断链路；保持单 API 进程、仅本机同源 HTTP、账号历史隔离、业务数据共享和确定性业务 / SQL 安全边界。

Change Profile: 持续维护的运行能力 / 跨部署工具、API、前端与可观测 / 高风险（权限、状态、数据恢复）/ Software Test + 隔离集成 + 真实业务与运行验收 / 默认本地 Commit，发布另行授权。

## User Stories

- 用户能判断当前能否发起问数 / 分析，故障时得到安全提示，恢复后重新操作。
- 管理员查看依赖、模型近期状态、执行额度及备份时间 / 失败原因。
- 本机操作者保留加密备份，在独立恢复环境核验，再显式切换并保留回退资源。
- 开发者通过阿里云诊断真实请求耗时与失败阶段；云端不可用仍可使用本地业务与诊断。

## Observable Behavior

### 1. 存活、就绪和模型状态

- `/health` 保持既有 HTTP liveness 语义与响应兼容。
- 就绪检查覆盖业务 / Control 数据库、Qdrant 及当前发布必需的业务 / RAG 资产与兼容状态，不能仅验证 TCP 端口可连接。复用既有权威校验，不另定义业务真相。
- 稳定服务运行且网页打开时，本地依赖故障或恢复在60秒内反映；检查超时 / 结果过期显示未确认，不能延用旧的正常状态。检查机制须有超时及有界资源开销。
- 不执行定时真实 LLM 探测。模型状态采用最近15分钟最后一次真实调用结果：最近调用成功、失败的安全分类、无近期证据则未确认；不承诺下一次调用成功。任务因其他原因失败不冒称模型失败。
- 就绪未通过时拒绝新的问数与经营分析，并给出安全原因；依赖恢复、检查通过后恢复受理。已受理任务仍遵守R4停止 / 失败 / 保存规则，不能健康检查直接伪造业务终态。
- API整体退出仍由操作者手动启动；不新增自动重启策略。网页无法访问时，本机入口能够呈现容器实际状态，不把操作记录中的running当作实时证据。

### 2. 业务与导出资源保护

- 问数 / 分析共用业务额度，沿用每账号1、单API进程4的保护上限及已有配置约束。
- 旧同步 Query API 纳入同一额度和就绪检查，正常成功 / 业务拒绝响应格式兼容；不通过兼容入口绕过额度。资源不足立即拒绝，不排队、不自动重试。
- 后台受理、重放、取消 / 超时正在停止、同步执行和异常释放的生命周期保持一致；幂等重放 / 观察不重复占额度，真实执行结束后才释放。
- 导出沿R5每账号1/API2独立计数；保护时限仍为问数180秒、分析1200秒、导出60秒。这些上限不代表容量已验收或延迟承诺。
- 不引入多worker / 多副本共享状态、请求自动重试或网关级每秒限流。

### 3. 本地状态提示和权限

- 普通网页账号仅看到必要的服务不可用 / 任务繁忙提示；详细依赖、额度、模型与备份状态仅管理员可见。
- 管理员可见备份失败、最近成功时间及超过24小时无成功备份的持续提示。
- `./local status` 提供容器事实、各依赖检查结果 / 时间、模型近期结果、执行额度与备份状态；读取不了某状态时明确未知，不编造健康结果。
- 诊断日志与网页不显示Secret、原始SQL、问题、结果行或敏感异常；Cloud Trace内容采集关闭。
- 状态查看不突破现有Cookie / Bearer / CSRF / RBAC；自动状态刷新不能延长30分钟Idle / 8小时Absolute登录期限，不能成为周期保活。
- 系统备份、恢复及切换由具备主机权限的操作者通过本机命令执行，网页不提供数据库恢复按钮。

### 4. 加密备份

- 覆盖完整 `chatbi_control`：账号 / 权限 / 审计 / Session、历史 / 成果 / 执行及分析checkpoint；覆盖业务数据库Sales Mart与Seed，以及恢复所需配置 / 发布版本清单。
- 恢复配置含敏感信息，只放入加密产物；备份私钥独立保存，不放进备份。文件与临时资源权限受限，不进入Git、日志或Trace。
- 模型文件、Qdrant派生检索索引按固定版本恢复或重建，备份保留重建所需的资产身份 / 来源，不能用未知版本直接重建后冒称相同资源。
- 数据卷之外的本机目录保存备份；范围防本机误删、数据卷损坏和升级失败，不承诺电脑 / 硬盘损坏后恢复。
- 运行期间每6小时自动备份一次，升级前备份；电脑 / Docker关闭期间不执行，启动发现最近成功备份超过24小时则提示并补备份。启动无有效备份按缺失处理，不显示已受保护。
- 日常备份不停服，使用数据库一致性快照；与升级 / 恢复互斥。备份数据、配置、角色和版本证据必须对应同一受保护发布，不能把两个数据库的任意不匹配快照拼成成功副本。
- 自动和升级前备份保留最近7天；仅新副本成功并完整性校验后清理过期副本。清理仅限已确认归属的备份，不跟随未知路径 / 符号链接、不误删私钥或回退资源。
- 日常备份失败保留服务与已有副本，显示安全原因与最近成功时间；超过24小时持续提示。升级前备份失败则拒绝升级，保持旧版本运行。
- age公钥用于自动加密，私钥用于恢复；完整性校验包含加密产物有效、清单 / 数据库内容可解析与身份完整。仅文件存在不构成成功备份。

### 5. 恢复与显式切换

- 允许最多丢失最近24小时新增历史 / 成果，以最新有效备份为恢复点；备份未成功或系统未运行期间如超出该目标，应明确不满足，不能声称无条件24小时保障。
- 恢复必须先进入身份与资源独立的环境，验证账号 / 权限、历史 / 成果、业务数据 / Seed、checkpoint及版本兼容，完成必需索引准备与就绪校验。
- 损坏 / 篡改备份、缺少或错误私钥、未知 / 不兼容版本、资源归属冲突均拒绝，稳定数据保持；不通过清空稳定卷解决失败。
- 验证通过后用户显式执行切换，保留原数据及环境身份用于回退；不能因隔离核验通过自动覆盖稳定环境。
- 旧登录会话失效，恢复后所有账号重新登录；未完成执行标记结果未确认、不自动重发，成功历史与成果可读，checkpoint原期限不延长。
- 条件性RTO为30分钟：备份 / 私钥 / 所需镜像 / 固定版本模型缓存可用，从开始恢复到数据库恢复、索引重建、登录并读取历史 / 成果均计时；镜像 / 模型下载时间另记。外部LLM故障单独判断。
- 保留与恢复操作遵守单个active稳定API与既有advisory lock / epoch，不同时运行两个对同一Control DB写业务状态的API。

### 6. 阿里云诊断链路

- 复用现有OpenTelemetry / OTLP，重新核验稳定环境到阿里云的实际接入，不用历史Trace验收冒称当前已接通。
- 覆盖网页问数 / 追问、经营分析、XLSX / PNG / PDF导出及同步Query API。记录安全耗时、真实阶段、错误码 / 分类，并正确关联后台线程与恢复尝试；不生成不存在的业务步骤。
- 原始问题、Prompt、SQL、结果和Secret采集关闭；控制链路属性 / 脱敏日志范围，云端失败不产生原始异常泄露。
- OTLP关闭、配置错误、超时或阿里云不可用不改变业务结果，不额外重试业务；出口队列 / 超时 / 关闭有界。
- 本地运行 / 备份提示保留，备份详情主要在本地查看。本目标不承诺阿里云Metrics / Logs / 云告警平台的完整建设。

## Implementation Decisions

以下行为依据逐项用户确认；以下技术承载方案随完整Spec整体确认，尚未据此编码。

| 决定 | 依据 / 边界 | Revisit Trigger |
| --- | --- | --- |
| 单API、本机稳定环境、既有模块内扩展 | 已确认使用场景；保持依赖方向与Domain业务真相 | 多机、多用户容量或公网目标改变 |
| 依赖就绪保护与共享执行额度 | 用户确认覆盖同步API及网页，维持正常响应兼容 | 授权/执行状态公共Contract需超出本Spec |
| PostgreSQL逻辑备份、标准一致性快照，恢复到独立资源 | PostgreSQL为现有事实源；业务Mart在运行期只读，Control与checkpoint同库；实现设计证明跨数据库身份一致性 | 业务库新增写入、快照无法满足恢复一致性 |
| age `v1.3.2` Linux amd64 固定发行包 | 用户确认age；2026-10-08从官方Release核实版本及包SHA-256；工具镜像中安装，宿主无新依赖 | 版本安全性/构建兼容性需要改变 |
| 独立备份工具 / 调度职责，复用稳定操作互斥 | 自动备份不把迁移凭据/私钥交给业务API；状态仅暴露安全投影 | 调度生命周期或权限边界无法满足行为 |
| OTel / OTLP阿里云 + 本地诊断 | 用户确认；复用已建立Port/Adapter，不新增云Provider依赖到Domain | 云后端改变或用户确认Metrics/Logs/告警范围 |

## Compatibility / Migration / Runtime Delivery

- 无已授权业务数据迁移或指标 / 语义变更；必要Schema / 状态演进须在Design说明兼容与回滚，若改变本Spec已确认范围返回用户确认。
- 同步API新受理保护会新增受控拒绝；正常响应、身份与业务正确性兼容；R4/R5行为与失败资源回收保持。
- 原R6 release / backup / 状态若缺失新资产只能显示未初始化/未知，禁止假定已有备份有效。密钥和备份初始化必须显式，不覆盖用户现有配置。
- 新固定版本先在隔离资源验收，发布/稳定升级范围需单独授权；不自动替换当前运行2b4a8c8，不升级开发环境。
- 本Spec确认不等于允许Push、PR、整机重启、永久IDM设置、替换/删除稳定数据或云端收费设置变更。实际恢复切换需具备该次目标/资源的明确操作授权。

## Testing Decisions / Acceptance

- 确定性测试：就绪成功/失败/超时/过期与恢复；非LLM定时探测、模型15分钟证据状态；管理员/普通用户/无身份可见性、无保活；同步与后台额度共享、重放不重复计数、取消/超时/异常释放。
- 备份测试：6小时/启动逾期/升级前门禁；快照身份、运行期一致性、age往返与篡改/错误key拒绝；失败保留、7天有条件清理、路径归属、无Secret输出。
- 隔离PG/Qdrant/Compose：数据库/索引/配置等故障60秒内反映和恢复；在线备份不破坏正常任务；从空独立资源恢复完整数据/权限/快照/Seed/索引，旧Session撤销与未完成执行隔离；兼容与不兼容、恢复中断和显式切换回退。
- 真实Windows浏览器：管理员/普通账号状态提示、问数追问分析/历史成果/三格式导出；验证状态刷新不延长登录期限，依赖恢复能再次操作。
- 阿里云实际OTLP接入：真实各类入口链路能查询，耗时/阶段/错误关联正确；关闭/配置错误/云不可用时业务与本地诊断兼容，内容采集关闭。云配置由用户安全填写到本地，不写入证据。
- 单用户容量报告：记录当前clean候选、机器/镜像/模型/Seed/RAG身份、案例、各项耗时和CPU/内存峰值；验证超额拒绝、失败/超时资源回收及随后可再次执行；不把1用户基线改称4任务并发容量承诺。
- 恢复演练满足已确认30分钟条件，报告包含起止、数据指纹/权限/成功读取/索引与资源身份、失败拒绝、切换和回退；没有原始敏感行。
- 按实际Diff判断Formal AI Evaluation受影响范围；业务链/模型资产未变的原报告仅复用原候选行为基线，不改称新候选已重跑。若受影响则重跑对应正式套件，保留失败与报告身份。
- 软件/运行/Business Acceptance/AI Evaluation分别记录，报告绑定候选与基线；Secret扫描、Diff、链接、适用静态检查及当前上下文Code Review为交付门禁。
- 故障注入、恢复演练和切换采用专用隔离资源；未经单独维护窗口授权不重启整机/Docker，不覆盖真实稳定数据或开发资源；临时账号/Session/资源按归属清理。
