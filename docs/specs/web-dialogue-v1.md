# 电脑端 Web 交互与身份

本文定义当前 React / TypeScript / Vite 电脑端入口、登录和两种模式的交互。持久历史、后台执行及结果展示分别见 [历史与成果](history-results-v1.md)、[执行规则](execution-streaming-v1.md)、[可视化](result-visualization-v1.md)。

## 功能行为

### 登录与权限

- 仅管理员创建指定账号，首版无公众自助注册。
- 同一账号的并发登录按数据库中的最新账号状态串行判定；错误密码达到 5 次后锁定 15 分钟，锁定期间拒绝登录。
- 浏览器使用 HttpOnly Cookie 携带登录凭证，仍由现有数据库 Session 验证账号状态、权限和期限；不在网页可读存储中保存原始 Session Token。
- 刷新后重新核验身份，成功后仍保持登录；没有“记住我”。沿用 30 分钟 Session Idle TTL 与 8 小时 Absolute TTL，不能由前端定时请求无限延长登录。Idle TTL 按后端成功身份校验规则计算。
- `must_change_password` 用户只能进入首次改密流程；改密沿用撤销该账号既有 Session 的规则，完成后重新登录。
- 管理员重置与用户自行改密并发时，按用户状态串行处理；重置完成后必须保留管理员设置的密码、首次改密要求和旧 Session 撤销状态。
- 有 `query.execute` 权限的指定用户可查询同一套销售数据；无权限时禁止业务请求。Web交互 不增加部门 / 区域行列隔离。
- 历史按账号隔离；指定用户共享同一套业务数据。
- 身份过期、账号切换或退出时清理两种模式的临时消息、结果、会话编号、分析任务编号与输入草稿。旧请求的迟到响应不能重新填充这些内容。
- 退出调用后端撤销 Session 并清除 Cookie；网络中断导致无法确认撤销时，清理页面私有内容并明确提示退出未完成、可重试，不宣称服务端会话已撤销，也不自动重新进入业务页面。

### 模式、输入与当前展示

- 默认“问数”；模式切换不自动识别意图，也不自动转换查询条件。
- 每种模式分别保留当前页面内的消息 / 结果与输入草稿；切回问数使用原有效 `conversation_id`。
- “新对话”用于问数，清空当前问数记录、草稿和会话编号；不清空独立的经营分析展示，也不代表取消后端执行。
- 经营分析每个新问题是独立任务，不读取普通问数条件，也不把上一份报告当作跨问题记忆。
- 去除首尾空白后为空的问题不发送；前端只做输入形状检查，不自己裁决业务指标与比较时期。
- 澄清 / 范围拒绝直接显示后端给出的安全说明。用户修改并提交问题后再走现有链路，不新增隐式多轮分析澄清状态。
- 刷新核验身份并按URL只读恢复当前历史；重新登录默认新问数对话，用户从私人列表选择旧记录。不自动重发问题。

### 普通问数

- 首轮发送完整自然语言问题，不携带 `conversation_id`；成功后保存服务端返回的编号。
- 后续问数携带该编号，保持现有语义修订、认证 / 授权与状态提交规则；客户端不能提交 SQL 或完整语义状态。
- 成功展示原问题、结果表格、返回行数、截断标识和可展开的 SQL。SQL 仅来自成功响应，不显示未经校验的候选 SQL。
- 保留列顺序与值含义，正确区分 `null`、零和空字符串；空结果明确显示“没有符合条件的数据”，仍是成功轮次。
- `truncated=true` 时提示仅显示有界结果，不声称这是完整数据；当前最多返回 100 行。
- 列类型、单位、口径与图表依据服务端可信说明展示，不从列名猜测业务含义。
- 后端明确失败不改变上一成功状态；`CONVERSATION_UNAVAILABLE` 提示新开对话并提交完整问题，不自动丢弃编号后把片段追问当首轮执行。

### 经营分析

- 继续通过自然语言输入完整问题。页面说明当前支持两个明确时期之间的毛利 / 人民币净销售额变化分析；不新增结构化筛选器或任意分析场景。
- 发送 `mode=analysis`、完整问题与客户端生成的 UUID `analysis_run_id`，不携带普通查询会话编号。
- 新问题生成新 ID；重试本次分析锁定原问题和原 ID，修改问题后属于新任务。
- 成功显示后端报告中存在的标题、摘要、趋势、关键发现、原因说明、建议，以及结构化任务证据。保留后端提供的归因数值与对账结论，不在前端重新计算或补写解释。
- 后台执行 报告生成期间可以逐步显示实际模型输出中的标题、摘要、关键发现、趋势判断、原因分析和行动建议，并明确标记为尚未校验；草稿按纯文本显示，不提供另存成果，也不展示归因数值、图表或任务证据。
- 只有最终报告通过既有结构 / 引用 / 业务校验并成功保存后，才以正式报告替换草稿。失败、校验失败或确认取消会清除本次草稿；断连时暂留页面已有文字并标记中断，重连以服务端当前快照为准。
- 不把分析相关变化包装成证据不能支持的深层原因；分析失败或证据不足时展示说明，不制造完整报告。
- 相同用户 / 原问题 / 原 ID 的手动重试沿用既有 checkpoint 行为：未完成恢复、完成后读取结果；过期或不匹配时显示后端受控错误，不静默用新 ID 重新执行。

### 请求进行中与恢复

- 页面一次只提交一个业务请求；等待时禁用再次发送、模式切换与“新对话”。仍可编辑下一条草稿、浏览已有结果、退出登录。
- 执行阶段来自真实后台状态，草稿标明未经校验；取消、观察与重连按执行规则，不展示虚构进度。
- 响应成功 / 明确失败后恢复操作；空结果也结束等待。当前请求与后续草稿分别保存，不能用编辑后的草稿覆盖原请求问题。
- 前端不自动重发业务问题；现有经营分析内部任务的一次基础设施重试不因此移除。
- 网络中断、客户端等待超时、无法识别的响应均不能证明后端没有完成，显示“结果未确认”。停止等待不等于取消服务器任务。
- 普通问数结果未确认时保留已有展示，刷新历史核对已提交状态；或新开对话并补全问题，不基于不确定上下文自动重试。
- 经营分析结果未确认时，允许手动“重试本次分析”，携带原 ID 与问题；不假设原请求已取消，任务状态观察及受理幂等见执行规则。
- 后端明确返回 `QUERY_TIMEOUT` 等受控失败与客户端等待超时分别处理；后者属于结果不确定。
- 登录失效先清理私有页面并要求重新登录；重新登录不能自动重发旧问题。权限拒绝不能以匿名或其他账号回退。

## 技术与职责边界

### 已确认的技术与架构决定

- React + TypeScript + Vite；同一套前端代码用于本地开发和生产打包。
- 本地开发通过 Vite 提供页面和同源 API 代理；上线时页面与 API 使用同一网站地址，生产凭证仅通过 HTTPS 传输。
- 复用 FastAPI，增加浏览器 Cookie 登录支持，保留既有 Bearer 客户端与测试的请求 / 响应兼容。
- 配套 CSRF 防护：覆盖登录、退出、改密及 Cookie 认证的业务 POST；不能只依靠 CORS。Cookie 使用 HttpOnly，生产使用 Secure，并设置适当 SameSite / 作用域。
- Cookie 与 Bearer 同时出现且指向不同身份时拒绝请求，不得静默切换用户；验证失败的显式 Bearer 不能回退到 Cookie。具体浏览器接口与 CSRF 机制见 [Web设计](../designs/web-dialogue-v1.md)。
- 前端凭证、输入、模型报告、SQL 和单元格均按不可信内容处理；用安全文本 / 结构化元素展示，不执行服务端返回的 HTML、脚本或 SQL。
- 不引入第二套指标、Prompt、SQL 生成、数据访问或授权逻辑；归因继续由既有确定性后端产生。
- 当前支持本机单API进程；不承诺多worker / 多副本共享状态。


## 验收标准

- 登录、首次改密、期限与撤销、Cookie / Bearer冲突、CSRF和权限失败不泄露私有数据。
- 两种模式独立，失败与结果未确认区分，迟到响应不能覆盖当前账号或成功状态。
- 桌面浏览器可完成问数、追问、分析、历史恢复、执行观察和适用导出；展示与后台证据一致。
- 文本与 SQL 作不可信内容安全展示，表格保持NULL / 零 / 空字符串区别。
- 软件与真实浏览器 / 模型验收分别保存，执行和报告身份遵循对应Spec。

## 支持边界

仅电脑端；无公众注册、第三方登录、多租户、行列级隔离或手机验收承诺。模式不自动路由，经营分析不继承问数条件。公网部署、多用户容量和多副本支持不在当前范围。
