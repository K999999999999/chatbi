## Problem Statement

R1–R4 已提供电脑端问数、结果图表、完成的经营分析报告、私人历史与独立成果，以及后台执行与流式反馈。用户尚不能把这些结果下载为可继续处理的数据文件、汇报图片和完整报告。

R5 让指定账号从既有成功快照导出文件，保证内容、口径、精度和证据与所选结果一致，同时沿用当前身份、归属与权限边界。

事实源：[Roadmap](../roadmap.md)、[产品范围](../product-scope.md)、[Architecture](../architecture.md)、[Domain](../../CONTEXT.md)、[R2 Spec](result-visualization-v1.md)、[R3 Spec](history-results-v1.md)、[R4 Spec](execution-streaming-v1.md)、[Evaluation](evaluation.md)、[Runbook](../runbook.md)。R3 PR #54 与 R4 PR #55 已合并；上述 baseline 是 R4 merge commit，不把此前 Evaluation 报告改称该提交的通过结果。

## Solution / Scope

| 导出对象 | 格式 | 核心用途 |
| --- | --- | --- |
| 成功查询结果 | XLSX | 在 Excel 中继续处理原始返回数据 |
| 可用的单张图表 | PNG | 插入文档与演示稿 |
| 已完成且通过校验的分析报告 | PDF | 阅读和分享完整报告及必要证据 |

- 支持当前成功结果、重开的历史结果、保存成果；无需先另存成果。
- 服务端读取有权访问的持久化成功快照；页面缓存、客户端数据与图表数值不构成导出事实源。
- 不执行业务查询、不调用模型、不获取全量数据，不重算指标或归因。当前查询快照最多 100 行，分析证据沿用各任务已有的返回范围。
- 原值、当时业务口径、截断与证据限制沿用 R2 / R3；元数据未确认时不得猜测列含义、单位或查询范围。
- 文件直接下载；不建立公开分享链接或服务器文件库。生成期间可有受控临时资源，但不长期保存导出产物。
- 单 API 进程范围内验收，复用既有 FastAPI、账号、权限、History Application / Store、Control DB 与前端图表规则。

Change Profile: 持续维护、跨前后端与运行环境；风险集中于数据精度、鉴权、文档完整性、渲染隔离与资源回收。完整 Spec 确认后设计审查，随后拆分 Ticket、执行 Readiness，再确认拆分及实施授权。

## User Stories

1. 把一次成功问数的数据下载为 XLSX，核对口径并在 Excel 中继续处理。
2. 把当前选择的图表下载为带必要说明的 PNG，用于汇报。
3. 下载正式分析 PDF，阅读完整正文、归因和引用证据，不依赖页面折叠状态。
4. 重新登录或服务重启后，从历史 / 成果下载当时快照，不触发新的业务执行。
5. 权限失效、记录删除或导出失败时获得受控提示，既有结果和续聊状态保持完整。

## Observable Behavior

### 1. 来源与一致性

- 用户明确选择成功轮次、完成的分析报告或独立成果及适用格式；具体路由 / DTO 在 Design 明确。
- 导出绑定所选快照，而不是在生成期间切换到对话最新结果。重新查询正在执行时，仍可导出此前已提交的成功快照。
- 分析草稿、未确认结果、失败 / 澄清 / 拒绝轮次不可作为成功导出来源。
- 旧结果使用当时保留的说明；不能以当前指标定义覆盖旧口径，也不把旧快照作为可执行业务条件或授权凭证。
- 导出包含结果时间与导出时间，两者明确区分。缺失的历史说明 / 时间不臆造；在 Design 中核实可用来源并定义缺失表达。
- 没有可用图表时提示原因；查询数据或正式报告仍可按适用范围导出。

### 2. XLSX

- 两个工作表：原始数据与结果说明。
- 数据表采用可信业务列名；未认证列保留原始列名并说明含义未确认。列顺序、行顺序与快照一致。
- 保留原始值，不把页面舍入后的显示值作为原值。Excel 可安全表达的数值使用数字单元格；高精度小数、超长整数与编号使用文本并在说明表注明。
- 确定性精度判定、文本编号识别和 NULL / 空字符串的无歧义表示在 Design 中明确；原值可还原、NULL / 空字符串 / 零可区分是不可降低的验收条件。不能用与真实文本冲突且没有类型说明的标记冒充原始值。
- 说明表包含原问题、可用指标定义 / 单位、时间与筛选范围、结果时间、导出时间、精度处理及截断提示；未确认说明按 R2 降级表达。
- 所有用户 / 模型 / 数据库文本按数据写入；`=` 等开头的内容不生成可执行公式，不自动生成外部链接。
- 空结果允许导出，保留列头与没有匹配数据的说明。
- 超出 XLSX 格式可完整表达的限制时受控失败；禁止库静默截断长文本等内容后返回成功。

### 3. PNG

- 每张图单独导出，保留当前选择的折线 / 柱状类型。
- 展示该图对应的全部快照数据；页面缩放、滚动与图例临时隐藏不减少导出数据。
- 包含标题、单位、可用查询时间与必要警示。截断结果标明仅包含部分数据，不能宣称完整结果。
- 产品因素贡献图使用当前选中的产品并标明名称；不能替换为另一个产品。
- 沿用 R2 图表适用规则、精度与缺失时段语义；不新增图表业务类型，也不生成当前语义不支持的图表。
- 中文、长标签与完整数据应可读，不通过页面当前视口截图遗漏图形；具体布局与尺寸策略在 Design 明确。

### 4. PDF

- 正文完整包含标题、摘要、关键发现、趋势判断、原因分析、行动建议。
- 有归因数据时包含两期指标、产品贡献图与表格，以及全部已返回产品的因素明细；不受页面当前选中产品影响。没有归因时省略该部分。
- 证据附录包含报告引用的查询任务、返回数据、指标口径与时间范围；不把引用任务替换成新查询或虚构证据。
- 保留证据不完整、任务失败 / 跳过、数据截断与未展示产品数量等适用限制说明。
- 来源信息包含原分析问题、可用报告完成时间与导出时间；不包含 SQL、内部日志、Prompt、模型推理或私有运行对象。
- 折叠状态不影响内容；分页后仍完整可读，中文可正确显示，正文应为可选取文本。表格、标签和图表不得被无提示裁掉。

### 5. 身份、归属与文件安全

- 每次导出由服务端核验当前登录、owner 及所需业务权限，沿用既有 Session / RBAC 与 Cookie / CSRF 边界。
- 不能仅凭旧页面缓存或记录编号生成文件。登录过期、权限撤销、账号不可用、记录删除或无权访问时受控拒绝，不自动重试；不泄露他人记录存在性。
- 生成 / 交付与权限撤销、记录删除的竞态需在 Design 中给出明确裁决点，保证交付仍满足当前访问检查，不持有长事务覆盖整个渲染过程。
- 模型报告、标题、问题、标签、原始值按不可信文本处理，不执行输入携带的 HTML / 脚本 / 公式，不读取输入指定的 URL 或本机文件。
- 渲染只使用应用提供的模板、图表资源和中文字体；生成期间禁止外部网络访问。渲染进程不持有用户 Session、LLM Key 或数据库凭证。
- 下载完成后文件是用户本机独立副本，退出登录或删除历史不会撤回该文件。

### 6. 资源与失败

| 限制 | 首版规则 |
| --- | --- |
| 来源快照 | 沿用 R3 单快照 5 MiB 上限 |
| 每账号同时生成 | 1 个文件 |
| 单 API 同时生成 | 2 个文件 |
| 单次生成总时限 | 60 秒，保护上限而非性能承诺 |
| 单个文件大小 | 20 MiB（20 × 1024 × 1024 字节） |

- 三种格式共用导出额度；导出额度与 R4 业务执行额度分别管理，不把导出当作新业务查询。
- 超额立即提示稍后重试，不排队、不自动重试；多个页面请求同样受服务端额度约束。
- 生成过程显示正在导出；完成或明确失败解除占用。超时须终止生成、确认资源回收再释放额度，不能只停止等待而遗留工作进程。
- 超时、超限、格式无法完整表达、缺少必要运行资源或生成异常时返回受控失败；不删行、删正文、删证据或返回损坏 / 部分文件来换取成功。
- 文件完整生成并通过适用检查后交付，生成失败不进入下载成功状态。下载中网络失败不重查业务，也不自动重试；用户可明确再次发起导出。
- 导出不改变历史、成果、业务执行终态或最后成功上下文；临时目录、生成进程与文件在成功 / 失败 / 超时路径均清理。服务重启不得留下可公开访问的产物或永久占用。
- 断连与生成进程清理的具体机制、重启遗留清理、缓冲与图形尺寸上限在 Design 中证明符合上述资源 / 完整性约束。

## Implementation Decisions

| 决定 | 依据与取舍 | Revisit Trigger |
| --- | --- | --- |
| 服务端统一生成，权威快照输入 | 用户逐项确认；避免浏览器缓存绕过当前访问检查 | 导出目标或权限 Contract 改变 |
| Python XlsxWriter | 显式类型与精度策略；禁止默认文本转公式 / 外部链接 | 文件格式或精度要求改变 |
| Playwright + Chromium 生成 PNG / PDF | 用户确认；复用既有 ECharts 图形规则，专用模板支持完整图表和中文分页 | 运行资源成本或渲染正确性无法满足验收 |
| 本地资源与中文字体，隔离生成 | 用户确认；不依赖外部字体 / CDN，超时可终止 | 目标运行环境改变 |
| PNG 使用 Noto CJK SC；PDF 使用 WenQuanYi Zen Hei | 独立 PDF 文本解析发现 Noto 的 Chromium ToUnicode 映射会把“民”“长”导出为部首码位；用户于 2026-10-07 确认只调整 PDF 字体，保留 PNG 字体 | PDF 中文提取或字体许可验收失败 |
| 只导出快照，不增加全量查询 | 用户确认；保持查询 / SQL Guard 与模型链路 | 用户独立确认全量导出 |

新增依赖及 Chromium / 字体安装纳入锁文件、容器开发和本地 Runbook；锁定版本、许可证与可分发字体、安装路径及验证工具在 Design 中核实，不在本 Spec 预填未经核实的版本。Application 通过 Port 使用文件生成 Adapter，Domain 不依赖文件库 / 浏览器 SDK；保持现有模块化单体，不新增远端渲染服务、通用任务平台或另一条业务查询链。

本 Spec 的技术事实参考 [XlsxWriter Worksheet](https://xlsxwriter.readthedocs.io/worksheet.html)、[Microsoft Excel 规格与限制](https://support.microsoft.com/en-us/excel/excel-specifications-and-limits)、[Playwright Page](https://playwright.dev/python/docs/api/class-page) 与 [Browsers](https://playwright.dev/python/docs/browsers)。这些资料证明基础 API 能力与 Excel 精度边界，不替代中文排版、资源回收或真实容器验收。

## Testing Decisions / Acceptance

1. 确定性文件测试：解析实际 XLSX / PNG / PDF，验证有效格式、列 / 行 / 文本 / 图形完整性、精度、NULL / 空字符串 / 零、危险文本、中文、长标签、空结果、截断及不完整证据；不仅检查扩展名或响应成功。
2. 权限 / 应用测试：当前身份、owner、权限撤销、记录删除、草稿拒绝、输入不可信、生成期竞态；证明导出没有调用模型 / 业务数据库查询或更新原状态。
3. 资源 / 故障测试：账号 / 全局额度、60 秒超时、20 MiB 文件边界、格式限制、渲染故障、断连 / 重启与临时资源回收；失败后可再次导出且既有记录完整。
4. 桌面浏览器：当前结果、历史、成果实际下载三种适用文件并检查内容，覆盖图表类型 / 产品选择与 PDF 不受折叠影响、权限和失败提示。
5. 隔离 Compose：真实登录、问数与分析生成成功快照，再导出并对照已保存值 / 口径 / 证据；覆盖中文字体、浏览器依赖、服务重启后的历史 / 成果导出。报告绑定最终 clean candidate、资源身份与范围，临时账号 / 凭证 / 容器清理可核验。
6. 受影响软件与前端回归、构建、模块边界、依赖与安全检查按仓库流程执行。
7. AI Evaluation：生成、检索和 SQL 链路不变且既有证据适用时复用并记录适用范围 / 基线差异；不宣称历史报告属于新 HEAD。若实现改变这些链路或原证据不再适用，按 Evaluation / Git 流程重跑受影响检查。

## Out of Scope

全量数据、分页扩大查询返回、重新查询或模型生成；CSV / SVG / DOCX 等额外格式；分析草稿导出；整段对话或全部历史批量导出；公开分享链接、服务器文件库；新增业务指标 / 归因 / 图形类型；手机、多数据源、多租户；多 worker / 多副本、远端渲染服务、队列 / 通用后台平台；R6 生产部署与 R7 容量运行承诺。
